## Как проверяли

`scripts/demo-functional-tests.mjs`: реальные Prisma, PostgreSQL, стандартные
Session/HMAC, ACL, Company/Club scope, исходные server actions и финансовые readers.
Тестовые адаптеры подменяют только границы Next (`cookies/headers` через
AsyncLocalStorage и cache invalidation); бизнес-логику, роли и данные они не подменяют.
Все сценарии создают собственные синтетические tenant и удаляют их после прогона.
`fetch` перехвачен с запретом внешнего вызова; попыток в сценариях не было.

`scripts/demo-finance-browser-tests.mjs`: Chromium, локальная production-сборка,
настоящие формы и HTTP server actions, без этих адаптеров. Проверяются изменения
в БД, два браузерных посетителя, reset, JS errors и запросы браузера.

## Что исправлено

1. В fixtures добавлен график выплат и синтетическое ИП филиала. Использована
   штатная статья `household` вместо несуществующего `supplies`; системные статьи
   инициализируются при создании набора. Реквизиты ИП/ООО настоящими не заполняются.
2. `payroll_payment` исключён из признанных расходов как погашение начисления.
   Убрано расхождение used/plan-fact/analytics с каноническим reader; добавлена
   дата признания для аналитических графиков. Оплаты продолжают создавать Expense
   для движения денег, но не удваивают P&L.
3. Начисление не исчезает на промежуточном статусе `accounting_review`.
   Пересчёт сумм синхронизирует обязательство календаря, в том числе после аванса,
   с использованием транзакции вызывающего сервиса.
4. Переход `mark_paid` блокируется при непогашенных остатках/неподтверждённых выплатах.
5. Для v2 возврата дата признания фиксируется при согласовании. Оплата в другом
   месяце больше не переносит признанный расход.
6. Добавлен явный безопасный путь синтетических документов для деморасхода и
   возврата: обычные ACL и авторство, только редактируемая запись своего tenant,
   генерируемые PDF, полный комплект слотов, нулевые вымышленные реквизиты. Реальные
   файлы по-прежнему не загружаются. У синтетических возвратных PDF разные ключи/hash.
7. В форме нового расхода деморежим передаётся явно; создание не требует файла,
   который сам стенд запрещает загружать. Новая запись проходит обычное согласование.
8. Подписи сводки уточнены: продажи исторические, расходы/планы учитывают изменения
   текущего демосеанса; прогноз расходов явно назван условным.

## Ограничения и решение о развёртывании

- Локальное QA пройдено. Новый Railway-проект/БД, публичный HTTPS host, реальные
  настройки ingress, секреты демостенда и cron очистки ещё не созданы/не проверены.
  Выполнять это только по отдельному разрешению; production URL приложения не менять.
- Региональное согласование остаётся обязательным этапом штатного процесса.
  Собственник не подменяет управляющего или бухгалтера. V1 запрос перерасхода и
  текущий v2 cash workflow проверены отдельно; их правила не объединялись обходом ACL.
- Работа с банком, ОФД, почтой, Telegram и ИИ отключена. «Оплачено» означает учётную
  операцию внутри демобазы, не отправку денег. Электронное подписание не реализовывалось.
- Базовые fixtures относятся к ноябрю 2026. Правила новых расходов по текущему месяцу
  сохранены; перед последующим обновлением периода нужен повторный QA, а не подмена
  времени авторизации. Линейный расходный прогноз учебный, не платёжный прогноз.
- Браузерный прогон — Chromium; отдельная ручная проверка Safari/iOS и публичного
  адреса не выполнена. Нагрузочное/длительное тестирование публичного хостинга не проводилось.
