# PWA cache policy — CLUB-OPS (финансовое приложение)

CLUB-OPS работает с деньгами, ОФД-чеками, персональными данными и документами. Ошибочно
закешированный ответ = показ **устаревших сумм** или **утечка чужих данных** на общем
устройстве. Поэтому политика кеша — **консервативная по умолчанию**: кешируем только то, что
неизменяемо и неконфиденциально.

Реализация: [`public/sw.js`](../../public/sw.js). Регистрация: только в production, через
[`PwaBoot`](../../src/components/pwa/PwaBoot.tsx) (в dev SW не активен — упрощает отладку и
исключает залипание кеша).

## Что кешируется (cache-first)

Только неизменяемые, обезличенные ресурсы (`isCacheableStatic`):

| Ресурс | Почему безопасно |
|---|---|
| `/_next/static/**` | Хеш в имени файла → immutable, меняется при каждом билде |
| `/pwa/icon-*`, `/icon`, `/apple-icon` | Иконки приложения, публичные |
| `/manifest.webmanifest` | Публичный манифест, без секретов |
| `/offline` (precache) | Статичная честная страница «нет сети» |

Механика: `cache-first` → при промахе `fetch` и кладём копию в версионированный кеш
`clubops-static-v1`.

## Что НЕ кешируется никогда

- **Навигации (HTML страниц)** — `network-first`. Онлайн → всегда свежий ответ с сервера.
  Оффлайн → честная страница `/offline` (а не устаревший экран с деньгами). HTML никогда не
  кладётся в кеш, потому что он может содержать авторизованные/финансовые данные.
- **API / данные / документы / ОФД / auth-сессии** — `network-only`. SW их не трогает
  (проходят напрямую в сеть). Оффлайн → штатная ошибка сети, без подмены старыми данными.
- **Не-GET запросы** (POST/PUT/DELETE — формы, действия) — SW сразу `return`, не вмешивается.
- **Кросс-ориджин** — игнорируется (`url.origin !== location.origin`).

Структурная гарантия проверяется в pilot (`SEC1`): во всём SW ровно **один** `.put()` (статик)
и **один** `.addAll()` (offline precache); в ветке навигации записи в кеш нет.

## Версионирование и обновление

- Имя кеша содержит `VERSION` (`clubops-static-v1`). На `activate` удаляются все прежние
  `clubops-*` кеши, отличные от текущего → нет накопления старых ассетов.
- Обновление SW — **контролируемое**: новый SW ждёт (`waiting`), `PwaBoot` показывает баннер
  «Доступно обновление». Перезагрузка происходит **только по нажатию** пользователя
  (`postMessage({type:"SKIP_WAITING"})` → `controllerchange` → один `reload`). Так мы не
  прерываем заполнение формы обновлением на середине.

## Секреты

Ни в манифесте, ни в SW нет токенов/паролей/ключей. Auth-токен живёт в httpOnly cookie
`club_ops_session` (см. [`src/lib/session.ts`](../../src/lib/session.ts)) — недоступен из JS,
не в localStorage, автоматически уходит с каждым запросом в standalone-режиме.

## Инвариант

> Если ответ зависит от того, **кто** вошёл или **сколько** денег — он не кешируется.
> Кешируется только то, что одинаково для всех и не меняется до следующего билда.
