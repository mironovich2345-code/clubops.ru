# WAVE 2 — производительность финансового контура на мобильном (§21)

Дата: 2026-07-28. Скоуп: расходы, счета, возвраты (+ их документы). Цель — быстро на мобильной
сети, без лишних данных/запросов. Метрики на реальном устройстве (Lighthouse/трассировка) —
в ручном чек-листе (не сняты из окружения разработки; зафиксировано честно).

## Архитектура (что уже хорошо)

- Server Components по умолчанию: списки/детали рендерятся на сервере, на клиент едут только
  интерактивные острова (формы, sheet, viewer). Системный шрифт (WAVE 1) — без веб-шрифтов.
- Финансовые страницы `force-dynamic` и **не кешируются** SW (WAVE 1 cache-policy) — всегда
  свежие суммы; кешируется только статик-шелл.
- Локальный preview файлов через `URL.createObjectURL` — без round-trip до сервера.
- Документы (PDF) во встроенном viewer грузятся **только при открытии** (`<object>` монтируется
  по клику), не предзагружаются в списке.

## Узкие места (по коду) и статус

| Место | Проблема | Статус в WAVE 2 |
|---|---|---|
| Списки расходов/счетов/возвратов | **Нет пагинации** — грузится весь scope (`getExpensesForScope`/`getInvoicesView`/`getRefundsForScope`) | Не введена в WAVE 2 (риск изменения серверных запросов/семантики). Помечено ниже как долг WAVE 3 |
| Счета — 3 таблицы на списке | Все три очереди рендерятся целиком | Мобильные карточки легче DOM-строки таблицы, но количество строк то же |
| Документы | Раньше открывались новой вкладкой (browser PDF) | Теперь ленивый встроенный viewer, PDF по клику |
| Audit history | На detail историю рендерят целиком | Не трогали (объёмы малы); lazy-секции — долг WAVE 3 |
| Мобильные карточки | +DOM vs таблица | Приемлемо; карточка показывает подмножество полей (меньше текста, чем 7 колонок) |

## Что сделано в WAVE 2 для перфа

1. **Ленивый просмотр документов** — `DocumentViewer`/`DocumentLink`: PDF `<object>` и `<img>`
   монтируются только при открытии; список не тянет файлы. HEIC/webp — честный download, без
   попытки рендера.
2. **Меньше layout-трэша на мобильном** — карточки вместо горизонтально-скроллящихся таблиц:
   нет reflow из-за `min-w-full`/`whitespace-nowrap`, нет второго (горизонтального) скролл-контейнера.
3. **Keyboard-aware sticky** через `visualViewport` — без тяжёлых слушателей скролла, только
   нативные `resize/scroll` visualViewport события.
4. **Клиентские острова малы** — StatusBadge/MobileListCard презентационные (Server Components),
   на клиент не отправляется их JS.

## Долги (WAVE 3, зафиксировано честно)

- **Пагинация/infinite-load** списков (expenses/invoices/refunds) + серверные `take/skip` —
  крупнейший перф-долг на больших клубах. Требует изменения серверных выборок (вне WAVE-2 скоупа
  «не ломать бизнес-логику малыми правками»).
- **Lazy-секции** истории/аудита на detail при больших объёмах.
- **Реальные метрики** (Lighthouse mobile, TBT/LCP на 3G-fast) — снять на устройстве по
  [iphone-wave2-finance-checklist.md](../testing/iphone-wave2-finance-checklist.md).

## Инвариант безопасности (перф не должен его нарушать)

Кеширование/предзагрузка НЕ применяются к финансовым/персональным данным. Любая будущая
пагинация/предзагрузка обязана оставаться в рамках [pwa-cache-policy.md](../architecture/pwa-cache-policy.md):
данные — network-only, свежие; кешируется только статик.
