# CLUB-OPS — Production Readiness Audit

Date: 2026-06-24
Scope: total audit of the current pilot deployment (`https://pilot.clubops.ru`), three clubs, multiple roles.
Method: parallel read-through of the actual codebase + targeted defect verification + regression tests. Builds and a deterministic pilot suite were run. Findings were verified against current code — not assumed from prior task summaries.

## 1. Executive summary

CLUB-OPS is a single-tenant-per-deployment Next.js App Router application with a mature security posture: DB-backed access control, mandatory password + email-OTP login, host-only session/OTP cookies, per-Company/Club isolation enforced at the final query, integer-kopek money, and an append-only audit log. The audit found **no open P0 findings** and **no open authentication, tenant-isolation, or financial-integrity P1 findings after the fixes in this task**.

Two real defects were found and fixed:
- **F-001 (P1, financial):** budget "used" and dashboard debt/cash-gap omitted the `approved_by_chief_accountant` status (the chief-accountant fallback approver), undercounting committed obligations. Fixed by sourcing all three sites from one canonical `APPROVED_UNPAID_STATUSES`.
- **F-002 (P2, auth resilience):** the SMTP transport had no timeouts, risking an indefinitely hanging login request on an unresponsive mail server. Fixed with bounded connection/greeting/socket timeouts.

One block remains conditionally incomplete by design: **backup/restore is documented but NOT verified by a real restore** (Phase 19). This does not block a controlled pilot but must be completed before relying on recovery.

## 2. Final readiness verdict

**READY WITH CONDITIONS.**

Conditions before/at pilot go-live (operational, not code):
1. Set production env: `DATABASE_URL` (Postgres), `SESSION_SECRET`, `OTP_SECRET` (distinct), `APP_URL=https://pilot.clubops.ru`, `SMTP_*`. Confirm `OTP_TEST_TRANSPORT` is unset.
2. Run `prisma migrate deploy` (production schema) before app start.
3. Execute one real isolated backup→restore test (see `BACKUP_RESTORE_RUNBOOK.md`) and flip that block to verified.
4. Send one live OTP email end-to-end on the deployed domain (SMTP cannot be exercised from this environment).

- **Financial services:** `analytics.ts`, `balance.ts`, `balance-snapshots.ts`, `payments.ts`, `payment-obligations.ts`, `expense-drilldown.ts`, `sales-reports.ts`, `invoices.ts`, `expenses.ts`, `refunds.ts`, `budgets.ts`, `approval.ts`, `legal-entities.ts`.
- **Files/AI:** `src/app/api/{expenses,invoices,refunds,sales-reports}/[id]/file/route.ts`, `src/lib/*-storage.ts`, `document-access.ts`, `src/lib/ai/*`.
- **CLI / cleanup scripts:** `scripts/security-change-email.mjs`, `security-reset-2fa.mjs`, `security-cleanup.mjs`, `cleanup-sessions.mjs`.
- **Pilot scripts:** `scripts/pilot-appurl|otp|sessions|club-legal-entity|financial.mjs`, aggregated by `pilot-full.mjs`.
- **Build/migrate commands:** `build` / `build:prod`; `prisma:migrate` (dev), `prisma:migrate:deploy` (prod), `prisma:sync-prod`.
