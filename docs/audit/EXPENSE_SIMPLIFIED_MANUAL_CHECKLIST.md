# CLUB-OPS — Упрощённый расход: ручной чек-лист (пилот)

Не использовать реальные документы/секреты. Прогонять на стенде.

## Foundation, реализованная в этой задаче (проверяется автоматически `npm run pilot:expenses-simplified`)
- Автозаголовок: «Категория: краткое содержание списка», без HTML, усечение.
- Дата: сегодня и ровно 7 дней назад — принимаются; 8 дней назад и будущее — отклоняются.
- Активное ИП клуба определяется автоматически; нет ИП / несколько ИП — блокируется с понятным сообщением.
- Бюджет: в рамках → бухгалтерия; перерасход ≤5% → РД; >5% → собственник; нулевой/отсутствующий бюджет при сумме >0 → собственник.
- Реализованный расход считается один раз (`verified` для v2, `confirmed` для legacy); черновик/отправлен/на согласовании/на исправлении/отменён — исключены.
- Статьи: главбух создаёт/переименовывает/отключает/восстанавливает; переименование сохраняет историю и не меняет ключ; отключённая недоступна для новых, историческая — читается.
- paidBy: удалённый/неактивный пользователь недоступен для выбора.
- Legacy `entryVersion=1` читается.

## Ручные сценарии (роль → шаги → ожидание)
1. Менеджер (телефон): создать расход — категория, сумма (числовая клавиатура), дата, комментарий, список покупок, кто оплатил, чек с камеры. Ожидание: одноколоночная форма, без горизонтальной прокрутки, значения сохраняются при ошибке загрузки.
2. Менеджер: попытка выбрать чужой клуб/ИП/способ оплаты — недоступно (сервер игнорирует).
3. Менеджер: отправка без документа — блокируется.
4. AI совпало: суммы/дата/список совпадают с чеком — статус «matched», без предупреждений.
5. AI расхождение: сумма в чеке ≠ введённой — предупреждение видно менеджеру/РД/бухгалтерии, сохраняется в истории, нельзя «тихо» стереть.
6. AI недоступен: провайдер не отвечает — `manual_review_required`, данные не теряются, отправка возможна, бухгалтерия видит пометку ручной проверки.
7. В рамках бюджета → сразу на проверку бухгалтерии.
8. Перерасход ≤5% → согласование РД → затем бухгалтерия.
9. Перерасход >5% → согласование собственника (только бюджетное исключение, без прав на прочее редактирование) → затем бухгалтерия.
10. Возврат на исправление (РД/собственник по своему решению/бухгалтер) с обязательной причиной; менеджер исправляет и повторно отправляет.
11. Отмена (менеджер/РД) с обязательной причиной; строка сохраняется (не удаляется), исключается из фактических итогов.
12. Бухгалтер: проверяет документы/сумму/категорию/дату/кто оплатил/AI-предупреждения/ИП+наличные → «verified». Повторная проверка идемпотентна.
13. Закрытый месяц: любые действия (создание/редактирование/отправка/согласование/проверка/отмена/изменение даты/документы) блокируются на сервере.
14. Управление статьями: главбух — можно; менеджер/собственник/бухгалтер — нельзя.
15. Наличные/ИП: расход уменьшает наличные соответствующего ИП один раз в статусе «verified».
16. Историческая запись legacy: открывается, поля показываются как есть, без принуждения к новым полям.
17. system_admin: не получает финансового доступа к расходам.

## Что НЕ входит в автоматический прогон (проверять вручную/на стенде)
- Реальная загрузка/предпросмотр/скачивание документов с телефона и авторизация перед скачиванием.
- Реальный ответ AI-провайдера (совпадение/расхождение/таймаут) — только на стенде с настроенным провайдером.
- Полный UI-переход по всем статусам на мобильном.
