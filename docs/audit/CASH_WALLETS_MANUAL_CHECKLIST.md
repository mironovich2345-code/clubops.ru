# CLUB-OPS — Кассы, движения наличных и «Приход Иное»: ручной чек-лист

Стенд. Точка входа: страница «Расходы» → «Касса» (`/expenses/cash`). Балансы
считаются ТОЛЬКО из подтверждённых движений (CashMovement). Целые копейки.

## Начальный остаток (региональный директор)
- [ ] До настройки Card 1 и «Касса» показывают «Требуется задать начальный остаток».
- [ ] Кнопка «Задать начальный остаток» видна только региональному директору клуба.
- [ ] Региональный директор задаёт начальный остаток (ИП, сумма ≥ 0, дата, комментарий) → баланс кассы КЛУБА обновляется (не кошелёк регионала).
- [ ] Единственное ИП подставляется автоматически; при нескольких ИП регионал выбирает; ООО/чужое/неактивное ИП недоступны.
- [ ] Нулевой остаток допустим; отрицательная сумма и будущая дата отклоняются; закрытый месяц блокирует.
- [ ] Повторная попытка задать начальный остаток отклоняется (одноразово, в т.ч. при параллельных запросах — понятное сообщение, не Prisma-ошибка).
- [ ] После сохранения показывается «Начальный остаток задан»: сумма, дата, ИП, касса клуба, автор, комментарий; форма повторного создания скрыта.
- [ ] Менеджер / бухгалтер / главбух / собственник / ГД / system_admin не могут задать начальный остаток.

## Расход → кошелёк
- [ ] Расход менеджера списывается из кассы клуба при статусе «Проверено».
- [ ] Расход, созданный региональным директором, списывается из ЕГО регионального кошелька.
- [ ] Проверка расхода уменьшает баланс один раз; повторная проверка не списывает дважды.
- [ ] Отмена до проверки не создаёт движения.

## «Приход Иное» (внешнее пополнение наличными — НЕ продажа)
- [ ] Создать приход (сумма + комментарий) → статус «ожидает подтверждения».
- [ ] До подтверждения баланс не меняется; продажи/выручка не растут.
- [ ] Получатель подтверждает → баланс клуба увеличивается один раз.
- [ ] Повторное подтверждение идемпотентно.
- [ ] Card 3 «Приход «Иное»» = сумма подтверждённых other_cash_income за текущий месяц (не продажи).

## Внутренние переводы
- [ ] Клуб → региональному: касса клуба уменьшается, кошелёк регионала растёт после подтверждения.
- [ ] Региональный → клуб: обратно.
- [ ] Суммарные наличные клуба (клуб + регионалы) не меняются при переводе.
- [ ] Недостаточно средств в источнике → перевод заблокирован.
- [ ] Повторное подтверждение перевода идемпотентно.

## Видимость (роли)
- [ ] Менеджер: видит только кассу клуба + агрегат «Передано региональному директору»; НЕ видит детали расходов/кошелька регионала.
- [ ] Региональный: видит кассу клуба и свой региональный кошелёк; не видит приватные детали другого регионала.
- [ ] Бухгалтер/главбух/собственник/ГД: видят «Всего наличных ИП» = клуб + регионалы с разбивкой.
- [ ] system_admin: без автоматического финансового доступа.

## Card 2 (временно, до OFD)
- [ ] «Приход наличных по ИП вчера» = подтверждённые наличные ИП (cash_ip) из сменного отчёта за вчерашний бизнес-день (временный адаптер; отдельно от other_cash_income).

## Прочее
- [ ] Изоляция между клубами и компаниями (нет утечки балансов/движений).
- [ ] Закрытый месяц блокирует создание прихода/перевода на дату закрытого месяца (где применимо).
- [ ] Legacy расходы и итоги не изменились.

## Не входит в автоматический прогон
- Реальные формы в браузере/на телефоне; реальное подтверждение получателем.
- OFD-интеграция (в этой задаче не реализуется; Card 2 — временный адаптер).
