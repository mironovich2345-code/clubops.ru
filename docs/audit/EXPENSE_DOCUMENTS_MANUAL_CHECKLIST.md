# CLUB-OPS — Документы расхода (Phase 2A): ручной чек-лист

Не использовать реальные документы/секреты. Прогонять на стенде. Раздел документов
виден на странице расхода `/expenses/<id>` для упрощённого расхода (entryVersion=2)
в статусе «Черновик» или «Требует исправления».

## Менеджер
- [ ] Загрузить один чек (JPEG/PNG/PDF) → появляется в списке с типом, размером, датой.
- [ ] Загрузить несколько файлов сразу → все принимаются; при ошибке одного остальные сохраняются.
- [ ] Загрузка с камеры телефона / из галереи / файлов (поле «Чек/документы»).
- [ ] Дубликат (тот же файл повторно в этот же расход) → «Такой документ уже прикреплён…».
- [ ] Неподдерживаемый формат (например .heic) → «Формат HEIC не поддерживается…».
- [ ] Слишком большой файл (>10 МБ) → «Файл слишком большой (максимум 10 МБ)».
- [ ] Более 10 документов / суммарно >40 МБ → соответствующее сообщение, лишние не сохраняются.
- [ ] Удалить документ с указанием причины → исчезает из активного списка (строка не удаляется физически).
- [ ] Закрытый месяц → загрузка и удаление заблокированы.
- [ ] Чужой клуб/компания: открыть расход не своего клуба — доступ запрещён (404/нет доступа).

## Бухгалтер / главбух
- [ ] Просмотр (inline) JPEG/PNG/PDF в рамках своей области.
- [ ] Скачивание документа (`?download=1`) доступно бухгалтерскому контуру.
- [ ] После проверки (verified) документы не редактируются менеджером (нет кнопок загрузки/удаления).
- [ ] Возврат расхода на исправление (через будущий workflow) — документы снова редактируемы.

## Владелец / ген.директор / system_admin
- [ ] Стратегический просмотр без прав изменять документы; system_admin не получает автоматического доступа к финансовым документам.

## Legacy (старый одиночный документ)
- [ ] Старый расход (entryVersion=1) с одним файлом открывается.
- [ ] Старый файл скачивается/просматривается по прежнему маршруту `/api/expenses/<id>/file`.
- [ ] Миграция или дублирование файла не требуется; в списке помечен «старый формат».
- [ ] Отсутствие необязательных метаданных не ломает страницу.

## Безопасность (проверить на стенде)
- [ ] Прямой доступ к `/api/expenses/<чужой id>/documents/<docId>` → 404 (существование не раскрывается).
- [ ] Storage-ключ не появляется в UI/URL; приватная ссылка не публичная.
- [ ] В логах нет тела файла/подписанных URL/секретов/токенов (только requestId + безопасные метаданные).

## Не входит в автоматический прогон (только ручная/стендовая проверка)
- Реальная загрузка/просмотр/скачивание файла в браузере и на телефоне.
- Реальное S3-хранилище (dev использует локальный диск).
- Поведение при недоступном хранилище (STORAGE_FAILED).
