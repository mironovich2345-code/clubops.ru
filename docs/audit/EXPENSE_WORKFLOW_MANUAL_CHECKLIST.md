# CLUB-OPS — Упрощённый расход: рабочий процесс (Phase 2B) — ручной чек-лист

Не использовать реальные документы/секреты. Стенд. Точка входа: «+ Новый расход»
на странице «Расходы» (для менеджера/РД). Форма: `/expenses/simple`. Деталь и
действия: `/expenses/<id>`.

## Менеджер
- [ ] Создать черновик на десктопе (7 полей: статья, сумма, дата, комментарий, список, кто оплатил, документы после создания).
- [ ] Создать черновик на телефоне (одна колонка, числовая клавиатура для суммы, date-поле, загрузка с камеры/галереи).
- [ ] Прикрепить один документ; затем несколько.
- [ ] Сохранить черновик и открыть заново (значения сохранены).
- [ ] Отправить (нужен ≥1 документ) → статус меняется по бюджету.
- [ ] Исправить после возврата и отправить снова (resubmit пересчитывает маршрут).
- [ ] Отменить с указанием причины (строка сохраняется, из итогов исключена).
- [ ] Убедиться, что НЕТ селекторов компании/клуба/ООО-ИП/способа оплаты/заголовка.
- [ ] Чужой клуб недоступен (открытие расхода другого клуба → нет доступа).

## Региональный директор
- [ ] Согласовать перерасход ≤5% → уходит на проверку бухгалтерии.
- [ ] Попытаться согласовать >5% → недоступно (маршрут собственника).
- [ ] Вернуть на исправление с причиной.
- [ ] Изменить дату в пределах 7 дней от создания (с причиной).
- [ ] Попытаться изменить дату после 7 дней → заблокировано.
- [ ] Отменить подходящий расход.

## Собственник
- [ ] Согласовать перерасход >5%.
- [ ] Согласовать расход без бюджета (owner-исключение).
- [ ] Вернуть на исправление.
- [ ] Убедиться, что обычные поля расхода недоступны для редактирования.

## Бухгалтер / главбух
- [ ] Просмотреть документы и данные.
- [ ] Проверить (verified) — только при статусе «ожидает проверки» и ≥1 документе.
- [ ] Вернуть на исправление.
- [ ] Убедиться, что после проверки расход попал в фактические итоги один раз и наличные ИП уменьшились один раз.
- [ ] Убедиться, что проверенный расход неизменяем (нет кнопок правки/документов у менеджера).
- [ ] Главбух: управление статьями (создать/переименовать/отключить/восстановить) — доступно; у остальных ролей — нет.

## Legacy
- [ ] Старый расход (entryVersion=1) открывается и читается.
- [ ] Старый документ скачивается по прежнему маршруту.
- [ ] Старый confirmed остаётся в итогах; данные не переписаны.

## Финансовая точка реализации
- Расход становится фактическим ТОЛЬКО при статусе `verified` (v2) / `confirmed` (legacy).
- Черновик/на согласовании/на проверке/на исправлении/отменён — НЕ входят в факт, бюджет-факт и наличные.
- Реализованный статус учитывается ровно один раз (EXPENSE_REALIZED_STATUSES).

## Не входит в автоматический прогон (ручная/стендовая проверка)
- Реальная загрузка/просмотр документов в браузере и на телефоне.
- Реальное S3-хранилище (dev — локальный диск).
- Реальное закрытие/переоткрытие месяца через UI (в тестах проверяется наличие защиты).
