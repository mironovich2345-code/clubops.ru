# Кассиры ОФД и личная выручка (STAGE 13)

Личная выручка сотрудника считается по **конкретным фискальным чекам** ОФД — через
**подтверждённое** сопоставление кассира ОФД с сотрудником. Никакого сравнения ФИО «на лету»
при каждом расчёте: строковое сравнение — только для предложения, которое подтверждает человек.

## Поток
Чек ОФД (с кассиром) → нормализация ФИО → **identity** (кассир в источнике) → предложение
сотрудника → **подтверждённый mapping** → атрибуция продаж → расчёт зарплаты.

## Экран «Кассиры ОФД» (`/payroll/ofd-cashiers`)
Для регионала / ГД / собственника. KPI (всего / подтверждено / авто / спорных / без
сопоставления / выручка без атрибуции), фильтры (клуб/статус), «Обновить из чеков». Карточка
кассира: ФИО из ОФД, клуб, чеки, сумма, предложение, действия (подтвердить / назначить вручную
/ исключить / дата действия) и **история сопоставлений**. Управляющий видит применённое
сопоставление только для чтения (в расчёте).

## Статусы сопоставления
- **Авто-совпадение** — точное совпадение ФИО с единственным активным сотрудником клуба
  (предложение, НЕ распределяет зарплату).
- **Спорный** — несколько кандидатов с таким ФИО → выбрать вручную.
- **Не сопоставлен** — совпадения нет → назначить вручную.
- **Подтверждён / Назначен вручную** — участвует в атрибуции.
- **Исключён** — из распределения выведен (история сохраняется).

Атрибуция идёт **только** по подтверждённым/вручную-назначенным сопоставлениям.

## Эффективные интервалы
У сопоставления есть «действует с/по». Переназначение кассира на другого сотрудника закрывает
старый интервал и создаёт новый — **исторические чеки сохраняют прежнего сотрудника**. Дата
чека решает, к кому он относится. Пересечение интервалов одной identity запрещено.

## Продажи в расчёте (блок «Продажи и возвраты»)
Для менеджеров/ночных/тренеров ГП: продажи ОФД, возвраты, чистая выручка, **ручная
корректировка** (перекрывает ОФД, не теряется), эффективная выручка, чеки, непривязанные чеки,
спорные возвраты, время синхронизации, источник. Кнопка **«Обновить продажи из ОФД»** — preview
→ apply через один attribution-сервис; пересчёт по формуле роли. Схему не меняет, денег не
двигает, Expense не создаёт.

## Возвраты
Возврат уменьшает выручку **исходного** менеджера продажи (не кассира возврата). Если исходная
продажа не найдена → **спорный возврат** (ручная очередь), случайного менеджера не уменьшаем.
Возврат по продаже прошлого **закрытого** месяца не меняет закрытый период — уменьшает выручку
в текущем открытом периоде даты возврата со ссылкой на исходную продажу.

## Правила по статусу периода
- Черновик — автообновление продаж допускается.
- На согласовании — новые чеки → предупреждение, нужен явный refresh/re-submit.
- Утверждён/выплачен — total автоматически не меняется (появление данных = отдельная задача).
- Закрыт — read-only.

## Что важно знать
- Кассир сохраняется только у Astral; Taxcom-чеки пока без кассира → `unmatched` (безопасно).
- Один физический чек влияет на зарплату один раз (в т.ч. если приходит из двух провайдеров).
- Схемы категорий: будущее изменение можно применить «на всю категорию клуба» (schemeScope).
