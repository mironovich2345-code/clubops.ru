# ГД / собственник: согласование версий схем (STAGE 12)

## Согласование изменения схемы (с будущей даты)
1. **ФОТ → Согласования** → откройте заявку `future_scheme_change`.
2. Смотрите before/after и обоснование. «Согласовать» → система **сразу создаёт новую версию
   схемы** с указанной даты (идемпотентно — второй версии не появится).
3. Если создание версии не прошло, статус остаётся «Согласовано (ожидает создания схемы)» —
   нажмите **«Создать версию схемы»** (безопасный повтор).

## Активация ручной версии
`/payroll/schemes` → цепочка версий → у версии «На согласовании»: **«Согласовать и
активировать»** (или «Вернуть» / «Отклонить»). При активации:
- вычисляется номер версии в логическом ключе;
- предыдущая открытая версия закрывается (`по` = дата новой) и становится «Заменена»;
- новая версия — «Действует» (или «Запланирована», если дата в будущем).

## Что важно
- Активная/заменённая версия **неизменна** — параметры не редактируются; новое изменение = новая
  версия.
- Resolver выбирает версию **по дате периода**: прошлые месяцы работают по своим версиям,
  будущие — по новой.
- Пересечение интервалов блокирует расчёт — исправьте настройки (это не молчаливый выбор).
- Snapshot прошлых расчётов не меняется никогда.

## Экран версий
Список цепочек (клуб, категория/сотрудник, текущая версия, статус, действует с/по, следующая,
конфликт) + сравнение версий (было/стало). Полный аудит действий сохраняется.
