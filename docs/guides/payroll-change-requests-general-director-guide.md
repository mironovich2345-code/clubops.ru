# Руководство ГД / собственника: согласование изменений зарплаты

Региональные директора **предлагают** изменения параметров зарплаты. Изменение вступает в силу
только после **вашего** согласования.

## Очередь согласований
**ФОТ → Согласования** (`/payroll/change-requests`).
- Карточки KPI: сколько на согласовании / на доработке / применено / отклонено.
- Фильтры по статусу, типу (разовые / будущая схема), клубу.
- Таблица (десктоп) или карточки (телефон): сотрудник, клуб, что меняется, **влияние на
  начисление**, статус, дата. Кнопка **«Рассмотреть»** открывает заявку.

## Карточка заявки
- **Было → Станет** и **влияние на начисление** (или «Невозможно рассчитать влияние», если нет
  базы — это не ноль, а честный признак отсутствия данных).
- Причина от регионала, комментарии, **история** всех действий и ревизий.
- Предупреждение о **переплате**: если новая сумма ниже уже выплаченной — покажем; авто-возврата
  не будет, урегулируйте вручную.

## Решения
- **Согласовать и применить** — изменение применяется **ровно один раз**:
  - разовая премия → отдельная строка начисления (деньги не двигаются);
  - процент/оклад/порог → пересчёт начисления по новой (эффективной) схеме; базовый snapshot
    сохраняется как есть;
  - будущая схема → статус «Согласовано (ожидает создания схемы)» — прошлые расчёты не
    затрагиваются, создание версии схемы выполняется отдельно.
- **Вернуть на доработку** — с обязательным комментарием; регионал доработает и пришлёт снова.
- **Отклонить** — с причиной; расчёт **не меняется**.

## Гарантии
- Заявка «на согласовании» **не влияет** на итог сотрудника до вашего решения.
- Повторное нажатие «Согласовать» не применит изменение дважды (идемпотентность).
- Нельзя согласовать заявку, поданную вами же.
- Разовое изменение периода **не меняет** живую схему; будущая схема **не переписывает** прошлое.
- Закрытый период защищён: применить к нему изменение нельзя, а период с незакрытой заявкой
  нельзя закрыть.
