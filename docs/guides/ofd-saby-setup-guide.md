# Подключение Saby ОФД (СБИС) — пилот

Saby ОФД (provider `saby`, ранее «СБИС ОФД») подключается через **официальный API**
(`api.sbis.ru`), кабинет <https://ofd.saby.ru/>. Провайдер за фиче-флагом
**`OFD_SABY_ENABLED`** (по умолчанию OFF) — доступен владельцу/системному администратору на
одном тестовом кабинете до сверки с реальными данными.

## Статус
`blocked_by_credentials`: эндпоинты построены по официальной документации, но схема
аутентификации и точные JSON-ключи чека должны быть подтверждены на реальном кабинете
(см. `docs/audits/ofd-saby-integration-audit.md`). До подтверждения `testConnection` честно
отказывает, а не имитирует вызов.

## Что реализовано
- Provider registry (`saby`, гейт по флагу), `SabyOfdClient` (host-allowlist
  api.sbis.ru/online.sbis.ru, заголовок `X-SBISSessionID`, timeouts, лимит ответа,
  `normalizeSabyError`), нормализация Saby-документа → общий `NormalizedOfdReceipt` с
  провайдеро-дедупом и захватом кассира.
- Безопасность: секреты encrypted, без логов секретов/сырого payload, SSRF-allowlist, retry
  auth один раз.

## Что проверить на реальном кабинете (перед включением)
Тело auth-запроса и lifetime сессии; точные JSON-ключи (кассир FFD-тег 1021, позиции, оплаты,
СНО); параметры пагинации и rate-limits; наличие ссылки возврата на исходную продажу; права
методов. Сверить итоги/позиции/возвраты/способы оплаты с кабинетом Saby на одной кассе за
ограниченный период, затем включать флаг.
