# Планирование выплат зарплаты — руководство

Когда период зарплаты **утверждён**, система создаёт **обязательства к выплате**
(`PayrollPaymentObligation`) — рельс «Зарплата к выплате» в платёжном календаре. Это числа **C→D**
в действии: начислено становится обязательством, выплаты уменьшают остаток.

## Откуда берётся обязательство
- Только из **утверждённого** периода (`approved | partially_paid | paid | closed`) — **не** из
  прогноза и **не** из черновика.
- Гранулярность: **юрлицо + клуб + категория + вид выплаты + дата**.
- Сумма = Σ `netPayableKopeks` по срезу — **авансы уже свёрнуты** (100 000 начислено + 40 000 аванс
  ⇒ 60 000 к выплате, а не 140 000).
- `remaining` = сумма − подтверждённые выплаты (пересчитывается из тех же `PayrollPayment`, **без
  параллельного реестра**).
- `idempotencyKey = company:club:legalEntity:category:period:final_salary` — повторный запуск
  **обновляет**, а не дублирует.

Генерация запускается при утверждении периода и обновляется при каждой записи/отмене выплаты
(`generateObligationsForPeriod`, идемпотентно).

## График выплат (по компании)
`payrollAdvanceDay`, `payrollFinalDay` (1–28), правило переноса с выходных
(`shift_earlier | shift_later | none`). Если день **не задан** — обязательство создаётся **без
даты** и **не попадает** в датированный календарь (дата **не выдумывается**), пока график не
настроят. Настраивают владелец / ГД.

## Три раздельных рельса в календаре (без задвоения)
| Рельс | Что показывает | Откуда |
|---|---|---|
| **Ожидаемый ФОТ** | прогноз (планирование) | `calculatePayrollForecast` — в календарь не пишется |
| **Зарплата к выплате** | обязательство | `PayrollPaymentObligation.remainingKopeks` |
| Факт | выплачено | `PayrollPayment` |

Ни одно число не появляется на двух рельсах: в календарь идёт **остаток** обязательства, а не
начисление; прогноз в `PaymentObligation[]` не попадает никогда.

## Выплаты, авансы, остаток, сторно
- Частичные выплаты добавляются (`PayrollPayment`), `paidKopeks`/`remaining` пересчитываются
  (`recomputeCalculationTotals`), обязательство обновляется.
- Переплата допускается существующей моделью и превращается в **долг сотрудника** при закрытии
  периода; остаток обязательства при этом ограничен снизу нулём (не уходит в минус).
- **Отмена обязательства** — только **главный бухгалтер**, с обязательной причиной; статус
  меняется на `cancelled`, строка **не удаляется** и **не воскресает** при повторной генерации
  (`cancelPayrollObligation`).

## Юрлицо
Каждое обязательство несёт `legalEntityId`; межюрлицовых и межкомпанийных связей нет. Если у
расчётов юрлицо не определено — они попадают в «Не распределено», а не размазываются.

## Эксплуатация
- Проверка данных (только чтение): `npm run preflight:payroll-budget-payment-planning`.
- Дозаполнение для ранее утверждённых периодов: `npm run backfill:payroll-obligations` (dry-run),
  затем `node scripts/backfill-payroll-obligations.mjs --apply`. Бюджет не меняется, черновики не
  затрагиваются, повтор безопасен.
