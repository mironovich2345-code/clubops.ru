# Отчёт: управление кассами ОФД

Полноценное редактирование привязок, безопасное удаление (hard/archive/purge), сохранение
истории. Не менялись: формат чеков, dedupeKey, финансовые движения, snapshot прошлых чеков,
provider-import Taxcom/Astral.

## Итог (§27, часть касс)
1. **Почему нельзя было удалить раньше.** Действия удаления не было; редактирование меняло
   только клуб+юрлицо in-place; hard delete оставил бы orphan-чеки/агрегаты/атрибуции.
2. **Что теперь редактируется.** ФН, РНМ ККТ, название, подключение, юрлицо, клуб, тип кассы —
   от даты («Действует с»). Без правки сырого JSON.
3. **История ФН.** `OfdFiscalDrive` — старый ФН → replaced, новый → active; чеки по фактическому
   ФН не переписываются.
4. **История клуба/юрлица/подключения.** `OfdCashRegisterAssignment` — end-exclusive интервалы;
   смена закрывает текущую и открывает новую.
5. **Hard delete.** Только для кассы без чеков/позиций/идентификаторов/атрибуций.
6. **Archive.** Касса с историей → status=archived, синхронизация стоп, привязка закрыта, чеки
   сохранены; скрыта из активных, видна по фильтру.
7. **Полное удаление.** Owner-only + ПИН + ввод ФН + dry-run preview + блок закрытым периодом +
   транзакция + audit до/после.
8. **Server-side guards.** requireOfdAdmin, PIN, tenant-проверка каждой ссылки, FN-conflict
   guard, closed-period guard, owner-gate для purge, IDOR.
16-19. **UI/Mobile.** Карточки от 320px, меню действий (Изменить/Вкл-выкл/Удалить), фильтр
   Активные/Удалённые/Все; без горизонтального скролла.
20. **Тесты.** `pilot:ofd-cash-register-management` 22/0.

## Критерии
Редактирование всех полей ✔; изменение привязки не переписывает историю ✔; пустую кассу можно
удалить ✔; касса с чеками архивируется без потери истории ✔; полное удаление защищено ✔;
mobile от 320px ✔.
