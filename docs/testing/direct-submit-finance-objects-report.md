# Отчёт: прямая отправка финансовых объектов (расходы, счета, возвраты)

Упрощение первичного создания: после нажатия основной кнопки объект сразу создаётся и
отправляется региональному директору — без отдельного шага «Отправить на проверку». Сохранены
цепочка согласования, проверка регионала, передача бухгалтеру, отклонение/возврат, документы,
права, история, уведомления, tenant isolation, финансовая логика.

## Финальный отчёт (§24)
1. **Раньше.** Расход/возврат: создать draft → отдельно нажать «Отправить». Счёт уже был
   draftless. Лишний шаг — у расходов и возвратов.
2. **Где было доп. подтверждение.** Расход — кнопка «Отправить» на детальной странице; возврат
   — кнопка «Отправить региональному директору» после мастера.
3. **Расход теперь.** Форма после успешной загрузки документов сама вызывает `submitExpense` в
   том же потоке → `pending_regional_budget_approval` (или `pending_accountant_verification` для
   расхода регионала). Подсказка под кнопкой + баннер об отправке.
4. **Счёт теперь.** `createAndSubmitInvoice` → `needs_review` сразу; кнопка «Создать счёт».
5. **Возврат теперь.** Финальное действие мастера «Создать возврат» = create-and-submit →
   `pending_regional_review`; без повторного подтверждения.
6. **State machines сохранены.** Использованы текущие статусы; после регионала — прежние
   переходы к бухгалтеру. Регионал не согласует сам себя (расход регионала → сразу бухгалтер).
7. **AI-анализ счёта.** Синхронный на загрузке; confidence отдельно от workflow-статуса; guards
   оплаты (low/medium+критичные поля) не тронуты; счёт не «висит» в draft из-за ИИ.
8. **Повторное исправление.** Возврат на исправление → `needs_correction` → «Исправить и
   отправить повторно» (расход/возврат). Не путается с убранным первичным draft.
9. **Idempotency.** Счёт — `clientSubmissionId @unique`; расход — draftId-reuse +
   `submitExpense` compare-and-set (`status in [draft, needs_correction]`); возврат — единый
   wizard-draft + compare-and-set. Double-click / повтор не создаёт дубли.
10. **Уведомления.** `notifyRegionalReview({resourceType})` для всех трёх; backfill — одно
    сводное уведомление на клуб (идемпотентно).
11. **Найдено старых draft.** Скрипт `finance:direct-submit-audit` (в проде подставит реальные
    числа: расходы / счета / возвраты). В деве база пуста → 0/0/0.
12. **Переведено автоматически.** `finance:direct-submit-backfill --apply` — по числам аудита
    (готовые draft каждого типа).
13. **Осталось на manual review.** Неполные/повреждённые (нет документа/регионала/scope/клиента/
    расчёта; автор-регионал у расхода) — с техническими ID в отчёте; не удалены, не угаданы.
14. **Автор и история.** `createdByUserId`/`createdAt` сохраняются; audit-событие
    `auto_submitted_after_direct_submit_migration`.
15. **Tenant.** Все действия scoped по company/club + IDOR real-DB тесты; backfill не пересекает
    tenant.
16. **Изменённые экраны.** `SimpleExpenseForm`, `expenses/[id]` (баннер), `InvoiceUpload`,
    `RefundWorkflow` + `refunds/new/[id]/details`, `refunds/[id]` (баннер).
17. **Mobile.** Одна основная кнопка ≥44px, блокируется на время запроса, без второго
    confirm-modal; подсказка помещается без горизонтального скролла (320px).
18. **Тесты/build.** `pilot:direct-submit-finance-objects` 31/0; expenses/invoices/refunds
    suites зелёные; tsc/next build/build:prod/prisma validate dev+prod; `pilot:full`.
19. **Commit hashes.** Серия `feat/test/docs(finance,expenses,invoices,refunds): …` (git log).
20. **Остаточные ограничения.** Расход технически создаёт запись до авто-отправки (если файлы
    не загрузились — остаётся draft с ошибкой, не отправлен; это не «нормальный успех»). Возврат
    использует wizard-draft как допустимое (§7) техническое состояние для сбора 4 документов.
    Backfill-уведомление — сводное по клубу (не по каждому объекту), чтобы не спамить.

## Критерии завершённости
После первого «Создать»: расход / счёт / возврат сразу у регионала ✔; доп. первичного
подтверждения нет ✔; после регионала — бухгалтерская стадия ✔; старые рабочие draft переводятся
регионалу ✔; повреждённые → manual_review, не потеряны ✔; повтор не создаёт дубли ✔; финансовая
и согласовательная логика цела ✔.
